# 知识库文档整理标准

> 适用范围：`data_dir/knowledge_base/` 下的全部文档与数据表。
> 目标：让文档可维护、可检索、可追溯，并让 RAG 检索结果稳定、引用来源清晰。

## 1. 设计原则

1. **单一入口**：所有入库文档只放在 `data_dir/knowledge_base/`，数据库、向量库、模型缓存不进入索引。
2. **主题优先**：按业务主题分类，不按文件格式、部门或创建时间分类；来源信息写进元数据或来源目录。
3. **一文一主题**：一个文件只回答一类问题，标题能独立表达主题，避免“汇编”“杂项”“其他”成为长期分类。
4. **内部与外部隔离**：内部工艺文件与外部采集文章分开存放，外部资料保留原文出处，便于复核和更新。
5. **数据与叙述分离**：参数、配方、缺陷对策等结构化内容用 CSV；流程、原理、操作说明用 Markdown。
6. **可增量索引**：文件内容不变则哈希不变，索引可直接复用；改名、移动目录会被视为新文档，需要重建索引。

## 2. 标准目录结构

```text
data_dir/
├── knowledge_base/                  # 唯一知识库根目录
│   ├── README.md                    # 目录说明与使用约定
│   ├── 00_原料与配方/               # 原料、化学组成、坯釉料配方
│   ├── 01_生产工艺/                 # 流程、参数、烧成制度
│   ├── 02_设备与窑炉/               # 设备、窑炉、点检维护
│   ├── 03_质量与检测/               # 检验、缺陷、抽检
│   ├── 04_标准与规范/               # 产品标准、试验方法、能耗环保
│   ├── 05_生产管理/                 # KPI、追溯、现场改善
│   └── 06_外部资料/                 # 外部采集资料，按来源分目录
│       └── 中国陶瓷网/
│           ├── 01_工艺技术/
│           ├── 02_设备窑炉/
│           ├── 03_质量检测/
│           ├── 04_标准与绿色制造/
│           └── 05_行业与市场/
├── conversations.db                 # 对话数据库（不索引）
├── milvus.db/                       # 向量库（不索引）
└── storage/                         # 索引清单与文档库（不索引）
```

### 分类边界

| 内容 | 归属 | 不应放入 |
| --- | --- | --- |
| 原料化学成分、配方比例、坯釉料设计 | `00_原料与配方` | 生产工艺流程 |
| 工序步骤、工艺参数、烧成曲线 | `01_生产工艺` | 设备采购新闻 |
| 设备结构、选型、点检、故障处理 | `02_设备与窑炉` | 产品质量标准 |
| 检验方法、缺陷判定、抽检结果 | `03_质量与检测` | 配方设计 |
| 国标/行标/团标、能耗与环保要求 | `04_标准与规范` | 企业宣传稿 |
| 产能、良率、能耗、OEE、追溯 | `05_生产管理` | 设备参数 |
| 行业新闻、展会、企业动态、市场数据 | `06_外部资料/<来源>/05_行业与市场` | 内部工艺文件 |

> 判断方法：先问“这份文档主要回答谁的什么问题”。主要回答工艺怎么做 → `01`；主要回答设备怎么选/怎么修 → `02`；
> 主要回答合格不合格 → `03`；主要回答依据什么标准 → `04`；主要回答管得好不好 → `05`。

## 3. 文件命名规范

### 内部文档

```text
<主题>_<子主题或文档类型>_v<主版本>.<扩展名>
```

示例：

- `陶瓷砖生产工艺流程与关键控制点_v1.md`
- `建筑陶瓷原料化学成分参考_v1.csv`
- `常见缺陷原因与对策_v1.csv`

要求：

- 使用中文主题词，不用“新建文档”“最终版”“副本”等词。
- 不用空格，统一用下划线；避免 `/ \ : * ? " < > |` 等文件系统保留字符。
- 版本号只在内容发生结构性变更时递增；小修小改用文档内“变更记录”记录。
- 日期只用于外部资料或有时效性的数据：`YYYYMMDD`。

### 外部资料

```text
<来源>_<标题关键词>_<文章ID>.md
```

示例：`中国陶瓷网_氢氨低碳燃烧技术_131767.md`

- 标题过长时保留前 40–60 个字符，不改变原意；文章 ID 用于溯源和去重。
- 同一来源、同一日期、同标题时，以文章 ID 区分。
- 外部资料不得改标题含义；可在正文前加“采集说明”。

## 4. Markdown 文档规范

### 4.1 来源元数据

内部文档在文首用一句话说明适用范围即可。外部资料统一在标题下方写来源引用块：

```markdown
# 文档标题

> 来源：中国陶瓷网 ｜ 发布日期：2023-06-08 ｜ 原文链接：https://www.ceramicschina.com/PG_ViewNews_xxxxx.html
```

同时在 `06_外部资料/<来源>/_采集清单.csv` 登记标题、日期、链接、分类和正文字符数。

不要在正文前使用 YAML front matter：索引器会把 front matter 当作正文切分，
产生只含元数据的片段，反而挤占检索结果。结构化元数据以采集清单为准。

### 4.2 正文结构

```markdown
# 文档标题

> 一句话说明适用范围和结论。

## 1. 适用范围
## 2. 关键概念
## 3. 流程 / 参数 / 方法
## 4. 异常与对策
## 5. 记录与检查
## 6. 参考资料
```

写作要求：

- 二级标题使用“对象 + 动作/问题”，例如“球磨工序关键参数”“中心裂的排查顺序”。
- 每节开头先给结论，再展开原因和操作细节。
- 参数必须带单位、对象和适用条件；不确定的数值明确标注“参考值，需按企业实际校准”。
- 原因分析统一用“现象 → 可能原因 → 排查方法 → 改善措施 → 预防要点”。
- 引用外部结论时在句末标注来源编号，并在文末列出链接。
- 不粘贴大段无上下文的图片说明、导航文字、版权声明。

### 4.3 检索友好性

系统按约 512 字切分、64 字重叠。为减少语义被截断：

- 每个二级标题下的内容尽量控制在 300–800 字。
- 关键实体（产品名、设备名、工序名、标准号）在段首出现，不要只用代词。
- 表格前后各写一句结论，避免表格被单独切出后失去上下文。
- 同一主题的多份文档使用统一术语；别名在首次出现时括号注明。

## 5. CSV 数据表规范

1. 编码 UTF-8（不带 BOM），逗号分隔，首行为列名。
2. 列名带单位，例如 `烧成温度_℃`、`含水率_%`、`压力_MPa`；无单位列写清口径。
3. 一行一条记录，不合并单元格，不用多行表头。
4. 空值留空，不写“无”“/”“N/A”等混用标记。
5. 数值范围统一用 `下限-上限`，不要混用 `~`、`～`、`至`。
6. 每张表至少包含：对象、参数/指标、参考值、适用条件、备注/来源。
7. 外部数据表在文件名或首列注明来源与日期。

## 6. 入库流程

```text
收集/编写
  → 去重（标题、正文首段、来源 URL）
  → 分类（按第 2 节边界）
  → 清洗（去导航/广告/图片说明，保留正文）
  → 命名（按第 3 节）
  → 元数据（来源、日期、链接、适用范围）
  → 放入对应目录
  → 更新索引
  → 抽检 5–10 个问题验证召回与引用
```

### 去重规则

- 同一 URL 只保留一份。
- 标题相同但正文相似度高的，保留信息更完整的一份。
- 同一主题的内部文档与外部文章可以共存，但内部文档应给出结论，外部文章作为证据。

### 更新与淘汰

- 标准、能耗限额、产品分级等时效性内容，标注适用年份；新标准发布后旧文档移到 `_archive/` 或删除。
- 设备型号、企业动态类文章超过 3 年，默认视为历史资料，不作为当前工艺依据。
- 删除文档前先确认没有其他文档引用其文件名。

## 7. 质量检查清单

- [ ] 文件在正确目录，文件名符合规范。
- [ ] 标题能独立说明主题，正文首段给出结论。
- [ ] 参数有单位、有适用条件、有“参考值”标注。
- [ ] 外部资料保留来源、原文链接、发布日期、采集日期。
- [ ] 没有导航栏、广告、图片说明等噪声文本。
- [ ] CSV 列名带单位，无合并单元格，无空行分隔的多张表。
- [ ] 同一主题术语一致，别名已注明。
- [ ] 更新索引后，用 3–5 个业务问题验证引用来源正确。
- [ ] 不包含 API Key、客户名单、未公开报价等敏感信息。

## 9. 采集合规

- 采集前查看目标站点 `robots.txt`，只抓取允许访问的公开页面。
- 控制请求频率（建议 ≥0.3 秒/次），不并发压站。
- 保留原文标题、来源、链接和日期；不修改原意，不去除署名。
- 采集内容仅用于内部知识库检索测试，不对外发布、不用于商业再分发。
- 站点改版或文章下架时，以原文链接为准进行复核。
